# Three-Door Rule

Adopted by the owner on September 10, 2026. This is a permanent implementation and release rule.

Every authoritative human workflow must identify its **Start**, **My Status**, and **Operator** destinations where applicable. A workflow is incomplete if its participant cannot find it, return to the same source record, recover from a partial failure, or receive its operator's outcome. A URL that works only when manually typed is not a human doorway.

Use the existing routes, authorization and visual organization. Review Center remains available to separately authorized non-admin reviewers. Economic Operations remains separate from community administration. Profile editors remain separate. A role may reveal an appropriate doorway but the destination must enforce its own authority again.

System callbacks, APIs, compatibility aliases and disabled provider handoffs need no human start button. Record-specific doorways must use authoritative IDs. If a destination ignores an ID, link to the canonical collection and label it honestly. Keep current implementations canonical; migrate worthwhile unique material before retiring a historical container. Preserve legal, consent and audit history.

For every changed workflow, update `three-door-workflows.json` and run `test:owner-decisions` plus the relevant database and browser tests. The contract is a release checklist, never runtime authority. Passing it does not activate payment or provider functions.

The policy's initial coverage follows the Whole-Site Closure Audit's 60 workflow groups. The executable contract below covers the workflows changed or explicitly reviewed by the owner-decision pass. Unchanged systems retain their existing route-preservation, authorization and workflow tests.
