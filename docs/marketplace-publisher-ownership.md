# Marketplace publisher ownership

Publisher identity is an entity, not an administrator role or an email address. An organization publisher has its own UUID and legal name; explicitly authorized Website Accounts manage it. Individual publishers retain the historical owner link for compatibility. A revoked membership overrides that compatibility link. Account deletion removes manager access without deleting the organization publisher or release provenance; private historical audit identifiers are retained under the existing operational-record governance.

`Creator / Organization` is editable attribution. `Publisher account` is an authorized publisher UUID. A Commons Profile display name can populate attribution but cannot grant publisher control. A manifest's declared author/publisher field remains separate and editable. Marketplace Submit, Forge home/new/template/edit/revision flows share `OwnershipAttribution`.

The authenticated workspace RPC returns only managed entities and their release references/listings. It never returns manager email addresses or manager user UUIDs. Public exact-release provenance exposes publisher UUIDs and immutable attribution snapshots, not private membership records. Client state is scoped to the current session; absent/malformed RPC data grants no authority.

SQL-owner-only governed operations establish organizations, delegate/revoke managers, and record existing external releases with an authorization basis and operation UUID. These operations have no browser, admin-role, economic-role or service API grant. Self-service creates an individual publisher or changes an authorized display name; it cannot create verification, legal-entity claims or delegation.

New cloud drafts require an authorized publisher and attribution. Browser-local drafts may keep attribution but do not establish a publisher relationship. Submission atomically locks its source draft and captures publisher provenance. Immutable snapshots are required before publication. Each published version retains its own source submission so later listing updates and profile renames cannot rewrite older provenance. New governed snapshots are unique per submission. The existing service-side deletion finalizer can perform only its verified archive/withdraw/revoke transitions; departing accounts do not revoke an organization’s published work or change immutable release attribution. Existing soft-deletion and retention contracts remain in place. Revisions preserve add-on identity and version until the creator deliberately changes the version for actual artifact changes.

Existing records with missing provenance remain historical and are not backfilled speculatively. Legacy direct publisher/catalog writes are closed; current intake uses Forge submissions. Reconcile unique historical content before retiring any remaining legacy container. A namespace conflict with an existing listing requires explicit reconciliation.

An external release reference is not a reviewed Marketplace listing. It can record an already distributed free artifact, exact version/hash/URL and publisher without fabricating review, publication, installation or financial events. It remains visibly distinct in Creator Studio; a later remote listing follows normal independent review. Never overwrite released bytes in place.

Marketplace review authority uses the existing Marketplace review domain. Submitters and anyone recorded as a manager of the publisher cannot approve or publish that publisher's work, including accounts that also hold admin/reviewer roles. Review Center remains at its existing routes and remains available to authorized non-admin reviewers. Publisher management does not transfer someone else's private draft to a new maintainer.

This model grants no seller/payment entitlement, processor credentials, Checkout, recurring support, paid credits, Connect onboarding or payout authority. Commercial preparation remains governed separately. Local Elysia retains install and execution authority. No financial flags or publication routes change in this migration.
