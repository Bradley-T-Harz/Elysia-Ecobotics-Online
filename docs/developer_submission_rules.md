# Developer Submission Rules

Developer submissions must include a complete manifest, security notes, source/homepage URLs when applicable, dependency declarations, license/provenance information, permission reasons, and a rollback/removal story.

Community submissions are never auto-approved. Review can request changes, approve, reject, deprecate, or place a submission on security hold.

Developers must not request local Elysia passwords, vault data, private files, dependency inventory, hidden tokens, or arbitrary command execution from the marketplace website.

Developers must not submit malware, spyware, credential harvesters, hidden telemetry, undisclosed network or filesystem behavior, unlawful material, or content they do not have the right to distribute. Do not include `.env` files, credentials, local logs, private memory, raw absolute private paths, browser profiles, or model tokens.

Choosing a repository, directory, source bundle, or `.elysia-addon` for local browser inspection does not upload it. Confirming private review transfer does: the selected bytes leave the computer and are sent to Elysia Ecobotics / EcoSyneva Commons review infrastructure. Review the exact selection first.

Submission does not mean approval; approval does not mean publication; publication does not mean installation; installation does not mean enablement; enablement does not mean unrestricted authority. Admin review reduces risk but does not guarantee safety.
